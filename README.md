# Аттестационная работа — комплект из 11 веб-проектов

## Состав
- `01_finance` … `10_service` — десять тематических многостраничных сайтов.
- `11_portfolio` — портфолио со ссылками на проекты.
- В каждом проекте: `index.html`, `about.html`, `contacts.html`, `style.css`, `script.js`, `robots.txt`, `sitemap.xml`, `DESIGN.md`.
- `дизайн макеты/` — 10 визуальных изображений макетов.
- `DEFENSE.md` — краткие вопросы и ответы для подготовки к защите.

## Запуск
1. Распаковать архив.
2. Открыть корневой `index.html` в браузере либо открыть папку в VS Code и запустить через Live Server.
3. Витрина ссылается на папки проектов относительными ссылками, поэтому сохраняйте структуру каталогов.

## Что реализовано
- Адаптивные страницы на HTML/CSS, Flexbox/Grid и media queries.
- Формы с HTML-валидацией и демонстрационной обработкой.
- Калькуляторы, фильтры, корзины, расписание, опрос, таймеры, аккордеоны, галерея, запись/бронирование и отзывы — в объёме, указанном на соответствующих страницах.
- В портфолио: поиск, переключение темы с localStorage и появление карточек при прокрутке.
- SEO-заготовки: title, description, keywords, robots.txt, sitemap.xml, canonical и Open Graph.

## Важные ограничения (не скрывать на защите)
Это учебные демонстрации. Формы не отправляют сведения на сервер, бронирования не являются реальными, расписание и цены вымышлены, корзина хранится только в памяти текущей страницы. Таймер рейса демонстрационный. Медицинские блоки не диагностируют заболевания. Для публичного использования понадобятся серверная часть, защита данных и реальные источники расписания/цен.

## Обязательные действия перед сдачей
- [ ] Заменить `https://ВАШ-ДОМЕН/` в canonical на реальные URL после публикации. Не оставлять заглушку.
- [ ] Проверить даты, тексты, цены, контактные данные и названия — заменить демонстрационные сведения на согласованные.
- [ ] Пройти все функции на каждом сайте в браузере, проверить ошибки в DevTools Console и мобильную ширину 360–390 px.
- [ ] Уточнить у преподавателя, достаточно ли одного хостинга с 11 папками или нужны отдельные поддомены.
- [ ] Опубликовать сайты на бесплатном хостинге. Пока публикация не выполнена, ссылки на живые сайты отсутствуют.
- [ ] После публикации обновить `canonical` и адреса в `sitemap.xml`/`robots.txt`.
- [ ] Подобрать семантическое ядро в Wordstat, переписать метатеги под реальные запросы.
- [ ] Создать собственный счётчик Яндекс Метрики или Google Analytics и вставить его код. Не использовать чужой идентификатор.
- [ ] Добавить оптимизированные WebP/AVIF изображения, осмысленные alt и при необходимости аудио/видео.
- [ ] Экспортировать макеты в отдельный PDF/PNG, если преподаватель требует отдельный файл (сейчас есть изображения макетов и текстовые спецификации).
- [ ] Загрузить исходники в собственный GitHub/облако и подготовить ссылку.
- [ ] Прочитать `DEFENSE.md` и потренироваться объяснять собственные функции по исходному коду.

## Техническая проверка
Проверяйте каждый сайт отдельно: главную, «О проекте», контакты, все формы, все кнопки, пустые/ошибочные значения, мобильный вид. Не заявляйте, что сайт опубликован или форма отправляет данные, пока это фактически не проверено.
